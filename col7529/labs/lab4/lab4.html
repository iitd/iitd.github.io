The value (at each program point) in Clang's analysis is encoded by using UncheckedOptionalAccessLattice = CachedConstAccessorsLattice; in clang/include/clang/Analysis/FlowSensitive/Models/UncheckedOptionalAccessModel.h. The CachedConstAccessorsLattice maintains two maps, namely ConstMethodReturnValues and ConstMethodReturnStorageLocations. The former tracks a storage location (e.g., a local variable) of record type (e.g., class, struct, union, ...) to its properties. One of the properties maps a const-qualified member function to the value it is expected to return (for a value type), and another maps it to a storage location it is supposed to return (for a reference type).

The joinConstMethodMap() function in clang/include/clang/Analysis/FlowSensitive/CachedConstAccessorsLattice.h implements the join operator for the semi-lattice.

Are the values copied at each program point (as we know that has quadratic space complexity)? Answer: The Environment object itself represents the program state (declarations, storage locations, mapped values, and path conditions) at a specific point in time. However, the complex heap-allocated elements within it (such as expressions, formulas, and values) do not live directly inside the environment. They are allocated in an Arena owned by the long-lived DataflowAnalysisContext. Environments store lightweight pointers (e.g., Value*, StorageLocation*, Formula*) pointing to these shared arena-allocated entities. When an environment is cloned or updated across CFG edges, only the mapping pointers are passed around—the underlying semantic objects are never duplicated. Inside the Environment, the maps that link program elements to their abstract states (like variable-to-location or location-to-value mappings) use llvm::DenseMap or persistent data structures (like llvm::ImmutableMap in parts of Clang's analysis suite): When moving from statement to statement, transfer functions create a shallow copy or delta modification of the mapping tables. Mappings that remain unchanged between basic blocks point to the exact same pointer addresses in memory.

How are meet-points (or join-points) handled, e.g., how are loops handled, do we have PHI nodes? Answer: no we do not have PHI nodes in Clang's AST representation. Instead, we have statements, that include loops, if-then-else statements, etc. The dataflow analysis infrastructure (implemented in clang/lib/Analysis/FlowSensitive/{TypeErased}DataFlowAnalysis.cpp) interprets a statement based on its semantics, e.g., for if-then-else, the values are transfered on the two respective branches, and joined at the end. Similarly, for loops (while, for, and do-while), the loop body is processed repeatedly, until a fixed point is reached at the loop header. To prevent infinite analysis loops on unbounded state spaces, the solver limits block visits using parameters like MaxBlockVisits.
